Building upgrades

Territory view → buildings that carry upgrades

An upgrade builds on a building already there. It takes no slot and no worker, and it adds to what its base does. Rural upgrades need only their tech; urban ones need the territory's tier, and they fall back (stop working) while the territory is below it, then return when it grows back. A base can carry several upgrades (a Farm takes both Ploughed Fields and Irrigation Canals) or a chain (Shrine → Temple → Great Temple).

Every option uses the same territory: Ur on a River Meadow, a Town at 9 pop. It holds a Farm with both rural upgrades, a Shrine with Temple and a fallen-back Great Temple (needs a Metropolis), a Market with a Merchant Quarter, and a Scribal School whose Library upgrade is on offer. Numbers are illustrative; balance comes later.

Recommendation: A (ribbons) for the face, X (a "+ Upgrade" chip opening the Build modal) to start one, and the stamped upgrade face in lists. One card per slot keeps the room-per-slot plan the territory view already draws, and each ribbon is one upgrade with its own added effect, so a fallen-back upgrade can be hatched on its own line with the idle look the guide already uses. Starting from the building reuses 297's Build modal rather than adding a second place to build.
1 · How an upgraded building looks on the territory view

A · Ribbons on the base card Recommended

The base card keeps its face. Each upgrade is a ribbon along its foot: the upgrade's name and what it adds. A fallen-back ribbon is hatched with the ochre lamp and the tier it needs. A building with an upgrade on offer shows a dashed + Upgrade chip, like the "+ Build" outline on an empty slot.

For
  • One card per slot: the row still counts slots at a glance.
  • Each upgrade's effect stays separate, which is how the engine resolves it.
  • Fall-back is per line, with the existing idle look.
Against
  • Cards with upgrades are taller than their neighbours; the row aligns to the bottom.
  • Three ribbons is about the most a compact face holds.

B · Upgrades as cards stacked behind

Each upgrade is a card tucked behind its base, its title strip showing above, like a pile on a slot. The top strip is the newest. A click opens the stack's details.

For
  • Reads as "cards on cards", true to a card game.
  • Base card face unchanged.
Against
  • Only the names show; what each adds is a click away.
  • Looks like a pile you could draw from, and a stack resembles the deck and discard counters.
  • Tall stacks push the row down unevenly.

C · One merged face

The card shows the building's total output as one set of rules ("⟳ +4 food"), its upgrades named in a sub-line, with a diamond per upgrade (hollow when fallen back). The details break it down.

For
  • Most compact; every card stays the same height.
  • Shows what the building makes now, the number you plan with.
Against
  • Totals need an engine query per building, and card text is generated per card today.
  • Fall-back is only a hollow diamond; the cost of shrinking is hidden.

D · Upgrades as half cards chained to the base

Each upgrade is its own small card right after its base, joined by an olive link: the engine's model drawn literally.

For
  • Each upgrade is a full card face with its own text and click.
  • Easy to build from today's card view.
Against
  • Upgrades look like they fill slots; the row no longer counts slots.
  • A realm with many upgrades runs off the screen.
2 · How you start an upgrade

X · "+ Upgrade" on the building opens the Build modal Recommended

297's Build modal gains an Upgrades heading under Buildings and Units, one row per upgrade a building here could take ("Library · on Scribal School"). The chip on a card opens the modal with that building's first upgrade selected. A tier-gated upgrade below its tier is listed dimmed with the reason, so you can see what growing would open.

For
  • One place to build anything on a territory, with 299's preview.
  • Dimmed rows teach the tiers.
Against
  • The list gets longer on a big territory (Upgrades can collapse when empty).

Y · From the building's details

Clicking the building opens its card details (as today), which gain an Upgrades section: each upgrade it could take, built or not, with an Upgrade key on the available one.

For
  • Everything about one building in one place, chain included.
  • No change to the Build modal.
Against
  • A second place to build, without the Build modal's preview.
  • You only find upgrades by opening each building.
3 · The upgrade's own card face (lists, a tech's Gives row, details)

Stamped upgrade face

The type line names the base ("Upgrade · Shrine"); every rules line starts with "Also", since it adds; a tier-gated upgrade carries a sage stamp with its tier. A rural upgrade has no stamp.
